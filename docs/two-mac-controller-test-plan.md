# 双机联动测试方案（主控机执行版）

状态：待执行  
日期：2026-07-17  
适用范围：两台 macOS 机器在同一局域网下，对 MouseBridge 做真实联动验证  
测试角色：

- 主控机：发送输入、发起连接、负责随时退出或终止测试
- 接收机：接收远端控制、观察注入效果、协助确认结果

## 1. 测试目标

本轮双机联动测试的目标是确认以下能力在真实两台机器上可用：

1. 主控机可以连接到接收机 daemon。
2. 首次联动可以通过 PIN 完成配对。
3. 主控机可以把控制权切到接收机。
4. 主控机可以把鼠标移动、点击、滚动、键盘输入真实注入到接收机当前 macOS 会话。
5. 主控机可以随时主动退出远端控制，并且不会把自己锁死在远端。
6. 主控机可以主动断开会话，结束测试。
7. 短时间重复切换、暂停、恢复后，系统仍能继续工作。

## 2. 完成标准

当下面条件全部满足时，本轮测试视为完成：

1. 预检查全部通过。
2. 首次连接与 PIN 配对通过。
3. 紧急返回路径验证通过。
4. 鼠标、点击、滚动、文本输入验证通过。
5. 至少完成一次“切到远端 -> 返回本机 -> 再次切到远端”的闭环。
6. 主控机可以主动 `Disconnect All` 结束会话。
7. 全程未出现无法返回本机、输入环路、daemon 崩溃、helper 失联无法恢复的问题。

## 3. 安全原则

本方案默认把“主控机可随时退出”放在第一优先级。

主控机在任何阶段都允许立即终止测试，优先级从高到低如下：

1. 按 `ctrl+alt+escape`，立即切回本机。
2. 在主控机 Web UI 执行 `Switch To Host`。
3. 在主控机 Web UI 执行 `Disconnect All`。
4. 用 HTTP API 从主控机本地执行：

```bash
curl -fsS -X POST http://127.0.0.1:39172/api/control/switch-to-host
curl -fsS -X POST http://127.0.0.1:39172/api/control/disconnect-all
```

5. 如果 UI 卡住但 daemon 还活着，直接关闭主控机 helper 或停止主控机 daemon。

终止判据：

- 主控机无法立刻回到本机。
- 接收机出现持续输入环路。
- 主控机或接收机 helper 反复断开。
- 任一侧 daemon 崩溃、长时间无响应、状态明显错乱。

## 4. 测试前置约束

1. 本轮测试只走“手动 PIN 配对”路径，不把 remembered 免 PIN 作为验收目标。
2. 两台机器都必须处于有人值守状态。
3. 两台机器都必须已经授予 helper Accessibility 权限。
4. 两台机器都必须能打开各自本地 Web UI。
5. 两台机器的 daemon 都必须监听非 loopback 地址，例如 `0.0.0.0`，并显式开启 `unsafe_http_lan=true`。

推荐配置确认项：

- `listen_host` 不是 `127.0.0.1`
- `unsafe_http_lan` 是 `true`
- `helper_runtime.connected` 是 `true`
- `helper_runtime.recommended_action` 是 `ready`

## 5. 测试前准备

### 5.1 主控机准备

1. 启动主控机 daemon。
2. 打开主控机 Web UI。
3. 在 `Setup` 页面确认：
   - daemon 已连接
   - daemon 正在监听
   - helper 已连接
   - helper 已授予 Accessibility
4. 在 `Settings` 页面确认以下快捷键存在且可用：
   - `switch_to_host`: `ctrl+alt+escape`
   - `switch_next`: 已配置
5. 打开一个终端，保留主控机本地终止命令：

```bash
curl -fsS -X POST http://127.0.0.1:39172/api/control/switch-to-host
curl -fsS -X POST http://127.0.0.1:39172/api/control/disconnect-all
```

### 5.2 接收机准备

1. 启动接收机 daemon。
2. 打开接收机 Web UI。
3. 在 `Setup` 页面确认：
   - daemon 已连接
   - daemon 正在监听
   - helper 已连接
   - helper 已授予 Accessibility
4. 打开一个安全的验证目标窗口。

推荐：

- TextEdit 新建空白文档
- 一个可安全点击和输入的普通窗口

### 5.3 联网确认

1. 主控机知道接收机的 `ip:port`。
2. 主控机可以从浏览器或终端访问接收机 `GET /api/status`。
3. 如果无法访问，先不要进入联动测试。

## 6. 执行顺序

按顺序执行，前一步不通过就不要进入下一步。

### 阶段 A：退出能力先行验证

目标：在真正切到远端之前，先确认主控机具备至少两条返回路径。

主控机操作：

1. 在 Web UI 找到 `Switch To Host` 和 `Disconnect All` 控件。
2. 确认本地终端中止命令可直接执行。
3. 确认键盘上 `ctrl+alt+escape` 可实际按到。

通过标准：

- 三条退出路径都已准备好。

失败处理：

- 任一条路径不可用，暂停全部测试，先修复。

### 阶段 B：连接与 PIN 配对

目标：确认主控机能连到接收机并完成首次配对。

主控机操作：

1. 打开 `Devices` 页面。
2. 对接收机发起 `Connect`。
3. 等待接收机显示 6 位 PIN。
4. 在主控机输入 PIN 并提交。

接收机观察：

1. 能看到待配对状态或 PIN。
2. 配对完成后能看到 active session。

主控机观察：

1. `sessions` 不为空。
2. 状态进入已连接。

通过标准：

- 会话建立成功。
- 双方 UI 都能看到活动会话。

失败处理：

- 如果连接失败，记录是网络、PIN、helper 还是 daemon 状态问题。
- 如果配对异常，先 `Disconnect All`，再重试一次。

### 阶段 C：主控机切到远端，再立即返回

目标：先验证最关键的安全闭环。

主控机操作：

1. 用热键或 UI 把控制切到接收机。
2. 在接收机上确认鼠标已受主控机控制。
3. 立即按 `ctrl+alt+escape` 返回主控机。

接收机观察：

1. 接收机短暂获得远端控制。
2. 返回后接收机不再持续接收主控机输入。

通过标准：

- 主控机能切过去。
- 主控机能立刻返回。
- 返回后主控机本地输入恢复正常。

失败处理：

- 先按 `ctrl+alt+escape`
- 再点 `Switch To Host`
- 再执行本地 `switch-to-host` API
- 如仍失败，立即停止测试

### 阶段 D：鼠标基础能力

目标：确认远端鼠标移动和点击可用。

主控机操作：

1. 切到接收机。
2. 在接收机窗口中做小范围移动。
3. 做一次左键单击。
4. 做一次右键单击。

接收机观察：

1. 光标移动平滑，无明显抖动或乱跳。
2. 左键点击生效。
3. 右键点击生效。

通过标准：

- 移动和点击都符合预期。

失败处理：

- 若出现跳跃、持续拖拽、点击错乱，立即返回主控机并记录。

### 阶段 E：滚动与文本输入

目标：确认滚动与键盘注入可用。

主控机操作：

1. 切到接收机。
2. 在 TextEdit 做垂直滚动。
3. 输入一段固定文本：

```text
MouseBridge dual-mac test
```

4. 再输入一段包含中英文和数字的文本：

```text
Hello 2026 你好
```

接收机观察：

1. 滚动方向正确。
2. 文本插入到当前焦点位置。
3. 没有明显重复字、丢字、卡键。

通过标准：

- 滚动正常。
- 文本输入基本准确。

失败处理：

- 如果输入失控或持续重复，立即返回主控机并断开会话。

### 阶段 F：重复切换闭环

目标：确认不是“一次性成功”，而是可重复使用。

主控机操作：

1. 切到接收机。
2. 返回主控机。
3. 再次切到接收机。
4. 再次返回主控机。

每次切换后都做一次最小动作：

- 远端移动一下鼠标
- 返回后本机移动一下鼠标

通过标准：

- 至少完成两轮切换闭环。
- 没有卡死、失焦、丢失返回能力。

### 阶段 G：暂停与恢复

目标：确认主控机能主动停掉转发，再恢复。

主控机操作：

1. 建立会话后切到接收机。
2. 触发 `toggle_pause` 或在 UI 执行暂停。
3. 尝试继续移动鼠标。
4. 再恢复。
5. 再次移动鼠标。

通过标准：

- 暂停时远端不再继续接收新输入。
- 恢复后远端继续可控。

失败处理：

- 如果暂停后状态错乱，立即返回本机并断开。

### 阶段 H：主动结束测试

目标：确认主控机能主动、安全地结束本轮联动。

主控机操作：

1. 确保当前已经回到本机。
2. 执行 `Disconnect All`。
3. 确认主控机与接收机会话都被清空。

通过标准：

- `sessions` 变为空。
- 主控机保持本地可控。
- 接收机不再接收远端输入。

## 8. 主控机快速终止卡片

主控机一旦感觉异常，按以下顺序执行：

1. 按 `ctrl+alt+escape`
2. 点 `Switch To Host`
3. 点 `Disconnect All`
4. 运行：

```bash
curl -fsS -X POST http://127.0.0.1:39172/api/control/switch-to-host
curl -fsS -X POST http://127.0.0.1:39172/api/control/disconnect-all
```

5. 必要时直接停止主控机 daemon

## 9. 本轮建议执行策略

建议我们按下面节奏推进：

1. 先完成第 5 节准备。
2. 我们从阶段 A 开始，严格按阶段逐项执行。
3. 每通过一项就更新本文件勾选状态。
4. 任一项失败时，先恢复本机控制，再判断是重试、跳过还是终止。
5. 只有在阶段 C 通过后，才进入真正的远端输入测试。
